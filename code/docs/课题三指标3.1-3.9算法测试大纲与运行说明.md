# 课题三指标 3.1–3.9 算法测试大纲与运行说明

## 1. 文档目的

本文档给出“面向离散制造垂域模型的自动化数据治理系统”指标 3.1–3.9 的算法文件、适用数据、测试范围、通过判据和逐项运行方法。3.1–3.7 为主要交付项，3.8–3.9 作为已实现能力一并提供。

## 3. 环境与通用运行方法

### 3.1 环境要求

- Python 3.11 或更高版本。
- 3.1–3.9 的核心测试仅使用 Python 标准库。
- 建议在固定机器、固定电源策略和低后台负载条件下执行性能测试。
- 所有命令均从项目的 `code` 目录运行。

```bash
cd code
python3 --version
```

### 3.2 逐项与全量运行

```bash
# 单项运行，3.1 可替换为 3.2 至 3.9
python3 run_indicator_tests.py 3.1

# 全部运行
python3 run_indicator_tests.py all

# 指定报告目录
python3 run_indicator_tests.py all --report-dir ./data/reports/acceptance
```

也可以直接运行测试文件：

```bash
python3 tests/individual/test_indicator_3_1.py
```

统一运行器退出码为 `0` 表示所选测试和对应算法基准均通过，非 `0` 表示至少一项未通过。默认报告目录为 `data/reports/indicator-tests/`。

### 3.3 通用证据要求

每次正式记录至少保留：源代码版本标识、JSON 报告、Python 版本、操作系统与处理器信息、测试数据说明、参数、重复次数、原始结果和异常日志。统一运行器会记录 Git commit、已跟踪文件的工作树状态、算法清单 SHA-256、参与测试的逐文件哈希和组合源码哈希；未跟踪本地文件不影响 `git_dirty`，交付内容完整性由 `PACKAGE_MANIFEST.json` 单独校验。不在 Git 工作树中运行时，commit 字段为空，但源码组合哈希仍可用于核对。3.3、3.4 报告样例数量、准确率及固定样例集合的描述性 Wilson 95% 二项区间；该区间不表示未抽样业务数据的总体准确率。3.5 报告预热次数、7 次同进程重复测量、每次吞吐、最低值、中位数、最高值和变异系数。任一基准异常都会作为失败结果写入报告，其余指标继续执行。

## 4. 指标 3.1：序列、关系数据存储与压缩

**指标目标：** 支持序列数据和关系数据的存储与压缩。

**算法文件：** `governance/indicator_3_1.py`；共用原子写入、文件锁与保留策略位于 `governance/common.py`。

**支持输入：** Python 对象数组。序列记录可包含时间戳、设备标识、数值和扩展字段；关系记录可包含工单、产品、工序、设备和有效时间窗等字段。字段值写入 SQLite 时按文本持久化。

**算法说明：** 序列数据编码为 UTF-8 JSON 后使用 Gzip 压缩；关系数据写入 SQLite，并生成数据库 Gzip 备份。文件采用原子替换，关系数据库访问使用路径锁和事务。

**测试数据与用例：**

- 2000 条合成序列记录与 3 条工单关系记录执行写入、回读和逐值比较。
- 解压 SQLite 备份并与原数据库字节比较。
- 使用含双引号字段名的关系记录验证标识符转义。
- 使用临时目录隔离功能测试产物。

**通过判据：** `sequence_round_trip`、`relation_round_trip`、`relation_backup_round_trip` 均为真，且序列压缩文件有效。压缩比作为证据记录，不作为 3.1 的单独阈值。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.1
```

**关键报告字段：** `sequence_records`、`relation_records`、`sequence_gzip_ratio`、三个往返校验字段及 `artifacts`。

## 5. 指标 3.2：工业时序数据压缩

**指标目标：** 工业时序数据压缩比达到 9:1。

**算法文件：** `governance/indicator_3_2.py`。课题组最新成果通过 `integrations/group_research/adapter.py` 接入，底层 Python 参考实现位于 `../reger_bos_code_paths/backend/myapp/reger_codec.py`，编码代价计算依赖 `../reger_bos_code_paths/backend/myapp/benchmark_loss.py`，相关 C++ 源文件位于 `../reger_bos_code_paths/cpp/src/`。

**支持输入：** PLA 接受一维有限数值时序；REGER 提供 Int64 与 Float64 无损接口；BOS 提供 Int64 无损接口；TS_2DIFF+BOS 提供 Int64 与十进制保持的 Float 接口。单次最多 2,000,000 个样本。

**算法说明：** 主指标使用有界误差分段线性逼近（PLA），在给定误差界内延长线性分段并压缩分段载荷。课题组 REGER、BOS、TS_2DIFF+BOS 算法统一封装为 `compress/decompress` 接口，并执行独立往返校验。REGER Float64 按逐元素精确相等判定；TS_2DIFF+BOS Float 采用十进制定点量化，按 `5e-7` 最大绝对误差界判定。

**测试数据与用例：**

- 5 个不同随机种子的平滑工业传感器序列，每个 12,000 点。
- 以 Float64 原始字节数除以压缩载荷字节数计算每个数据集压缩比。
- 校验最大绝对重构误差不超过配置误差界 0.08。
- 对 5 个课题组算法接口执行样本数、数值和载荷往返校验，其中 REGER Float64 必须精确一致。
- 验证负误差界、NaN 和非法载荷被拒绝。

**通过判据：** 5 个 PLA 数据集中的最低压缩比不低于 9.0；最大绝对误差不超过 0.08；课题组最新成果的 5 个适配接口全部往返正确。REGER Float64 必须精确一致，TS_2DIFF+BOS Float 最大绝对误差不超过 `5e-7`。REGER、BOS 和 TS_2DIFF+BOS 的压缩比单独披露，不与 PLA 的 9:1 指标混合计算。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.2
```

**关键报告字段：** `minimum_compression_ratio`、`compression_ratio`、`configured_error_bound`、`max_absolute_error`、`median_round_trip_ms`、`research_group_algorithms`。

## 6. 指标 3.3：序列、关系数据智能解析

**指标目标：** 序列、关系数据解析准确率不低于 95%。

**算法文件：** `governance/indicator_3_3.py`。固定标注资源为 `governance/benchmark_data/indicator_3_3_labeled.json`。

**支持输入：** CSV、TSV、分号分隔表格、管道分隔表格、JSON 对象数组、带 `records/data/rows/items` 包装的 JSON，以及 JSONL。最多 500,000 条记录和 2048 个字段。

**算法说明：** 自动或显式识别格式，增量限制记录数与字段数，将输入归一为 `format/records/columns` 结构，并拒绝标量记录、重复或大小写歧义字段、错误列数、非法 BOM 和格式错误内容。

**测试数据与用例：**

- 120 个有效标注样例，覆盖 6 类格式、可选字段缺失、字段换序、尾部空行、含分隔符的引号字段及 JSON 转义文本；样例与预期值保存在独立 JSON 文件中。
- 8 个无效样例，覆盖错误格式、非对象记录和结构异常。
- 使用代码常量和算法清单中的 SHA-256 锁定样例版本，哈希不一致时基准直接失败。
- 功能测试额外验证六类格式及重复字段拒绝行为。

**通过判据：** `parsing_accuracy_percent >= 95.0` 且 `failure_count == 0`。准确率按有效解析与正确拒绝的总正确数除以总样例数计算。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.3
```

**关键报告字段：** `fixtures`、`valid_fixtures`、`invalid_fixtures`、`correctly_parsed`、`parsing_accuracy_percent`、`accuracy_wilson_95_percent`、`accuracy_interval_scope`、样例指纹。

**统计边界：** Wilson 区间用于描述当前固定样例集合上的二项正确率波动范围。由于样例并非从全部业务数据总体中概率抽样，不应将该区间解释为生产环境总体准确率的置信区间。

## 7. 指标 3.4：异构数据语义时序对齐

**指标目标：** 序列、关系数据对齐准确率不低于 90%。

**算法文件：** `governance/indicator_3_4.py`。固定标注资源为 `governance/benchmark_data/indicator_3_4_labeled.json`。

**支持输入：** 序列对象数组与关系对象数组。支持中英文设备、时间和数值字段别名；关系记录可提供开始与结束时间窗；设备标识支持受阈值控制的模糊匹配。

**算法说明：** 先执行字段别名规范化和设备标识归一，再按设备候选、时间距离、时间窗宽度、中心距离和稳定键排序。多个窗口同时命中时优先选择距离更近且范围更精确的记录。

**测试数据与用例：**

- 150 个正样例，交替使用中英文字段名，包含设备标识轻微差异。
- 每个正样例同时提供宽窗口和精确窗口，标注精确工单为正确结果。
- 3 个负样例覆盖非法时间戳、未知设备和缺失设备。
- 1 条非法关系记录验证错误隔离。

**通过判据：** `alignment_accuracy_percent >= 90.0`。报告同时给出正确数、样例数、负样例数、模糊匹配样例数和固定样例集合的描述性 Wilson 95% 二项区间。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.4
```

**关键报告字段：** `samples`、`correct_alignments`、`alignment_accuracy_percent`、`accuracy_wilson_95_percent`、`accuracy_interval_scope`、`time_tolerance_ms`。

**统计边界：** 当前区间只描述版本化固定样例集合，不支持对未抽样设备、工况或数据源进行总体推断。面向生产数据的泛化评估应按设备类型、数据源和工况分层抽样，并冻结独立测试集。

## 8. 指标 3.5：1.1kHz 时序采集

**指标目标：** 时序数据采集频率达到 1.1kHz，即至少 1100 样本/秒。

**算法文件：** `governance/indicator_3_5.py`。

**支持输入：** 由对象记录组成的可迭代批次。默认缓冲容量 250,000 条，默认单批最多 20,000 条；容量和批次上限可配置。

**算法说明：** 使用锁保护的有界 `deque` 接收批量数据，记录累计接收量并支持最近数据快照。批次预先限长，避免无限生成器或超大批次耗尽资源。

**测试数据与用例：**

- 先执行 1 次不计入结果的预热，再在同一 Python 进程内测量 7 次；每次接收 120,000 条记录，批大小 1000。
- 每次校验累计接收数和快照记录数，确认无记录丢失。
- 报告每次、最低、中位、最高吞吐及变异系数，使用最低吞吐判定。
- 功能测试验证环形覆盖语义及超限批次拒绝。

**通过判据：** 7 次测量的 `minimum_samples_per_second >= 1100` 且 `lost_samples == 0`。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.5
```

**关键报告字段：** `samples`、`repeats`、`warmup_runs`、`run_samples_per_second`、`minimum_samples_per_second`、`ingestion_samples_per_second`、`maximum_samples_per_second`、`throughput_coefficient_of_variation`、`lost_samples`。

**测量边界：** 7 次结果是同一进程、同一机器上的重复测量，用于估计短期运行波动，不属于 7 个独立硬件重复。当前结果衡量 Python 进程内缓冲区的软件接收能力。若验收范围包含传感器、采集卡、驱动、网络和持久化链路，应在指定硬件上按机器或采集链路设置独立重复，并追加端到端采样率与丢包率测试。

## 9. 指标 3.6：数据质量稳控

**指标目标：** 完整性、一致性、时效性、有效性均不低于 95%。

**算法文件：** `governance/indicator_3_6.py`。

**支持输入：** 包含 `timestamp_ms`、`equipment_id`、`value` 的对象数组。可显式设置评测时刻和允许的最大数据年龄。

**算法说明：** 完整性检查必填字段；一致性检查同设备时间单调性；时效性按显式评测时刻计算数据年龄；有效性检查设备非空、时间戳和值的类型、有限性及范围。

**测试数据与用例：**

- 5000 条序列记录，注入 6 处已标注异常。
- 异常覆盖缺失值、空设备、非法时间戳、无穷值、过期记录和局部时间乱序。
- 额外以历史时间戳和显式当前时刻验证过期数据不能获得满分。
- 验证对象数组以外的输入及负最大年龄被拒绝。

**通过判据：** 四个维度分别不低于 95%，即 `minimum_dimension >= 95.0`。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.6
```

**关键报告字段：** `completeness`、`consistency`、`timeliness`、`validity`、`minimum_dimension`、`reference_time_ms`、`max_age_ms`。

## 10. 指标 3.7：序列、关系数据融合

**指标目标：** 序列数据与关系数据可按设备实体和时间窗进行融合。

**算法文件：** `governance/indicator_3_7.py`；复用 `governance/indicator_3_4.py` 的对齐算法。

**支持输入：** 序列对象数组和关系对象数组。序列数据可包含时间戳、设备标识、数值；关系数据可包含设备、工单、产品、工序和有效时间窗。

**算法说明：** 对齐后执行左融合。原序列字段保持不变，命中的关系字段增加 `relation_` 前缀，同时保留对齐状态、距离、原因和实体匹配方式；未命中序列记录仍保留。

**测试数据与用例：**

- 5000 条序列记录与 3 条关系记录执行融合并统计命中数和吞吐。
- 构造一条命中、一条未命中的最小数据，验证左融合行数不变。
- 验证命中记录携带工单字段，未命中记录不产生伪关系字段。

**通过判据：** `fused_rows == sequence_rows` 且 `matched_rows > 0`；功能测试中的命中和未命中语义均正确。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.7
```

**关键报告字段：** `sequence_rows`、`relation_rows`、`fused_rows`、`matched_rows`、`rows_per_second` 和 `preview`。

## 11. 指标 3.8：工业异构数据规范化测试框架

**测试数据与用例：** 8 种格式各 1 个正确标注样例；5 个异常样例覆盖错列、标量 JSON、混合 JSONL、外部实体 XML 和无配置节 INI；另验证自定义适配器注册。

**通过判据：** 8 种格式全部得到标注结果，5 个异常样例全部被拒绝，`failed_formats` 为空。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.8
```

**关键报告字段：** `registered_adapters`、`tested_formats`、`passed_formats`、`failed_formats`、`rejected_invalid_fixtures`。

## 12. 指标 3.9：工业数据质量综合测评

**指标目标：** 支持 5 个以上维度的工业数据质量综合测评。

**算法文件：** `governance/indicator_3_9.py`；四个基础维度复用 `governance/indicator_3_6.py`。

**支持输入：** 工业对象记录数组及可选主数据字典。默认主数据检查 `equipment_id` 和 `work_order`，也可传入其他字段及允许值集合。

**算法说明：** 在完整性、一致性、时效性、有效性基础上增加唯一性、主数据参照完整性和分设备稳定性，共 7 个维度。参照完整性按实际参与检查的字段值计分，稳定性采用中位数和 MAD 的稳健异常判断。

**测试数据与用例：** 5000 条记录注入未知设备、重复记录和极端值；额外构造自定义设备与工单主数据，验证未知设备降低参照完整性；验证空输入返回零综合分。

**通过判据：** `dimension_count >= 6` 且 `minimum_dimension >= 95.0`。

**运行命令：**

```bash
python3 run_indicator_tests.py 3.9
```

**关键报告字段：** `dimension_count`、`dimensions`、`overall_score`、`minimum_dimension`、`referential_checks`、`master_data_fields`。

## 13. 结果判读与归档

1. 查看终端最后一行是否为“结果: 通过”，并确认进程退出码为 0。
2. 打开最新 JSON 报告，核对 `passed`、`tests`、`benchmarks` 和 `environment`。
3. 对 3.2 核对最低压缩比和最大误差，不使用平均压缩比替代最低值。
4. 对 3.3、3.4 同时保存样例规模、准确率和描述性区间；只有采用预先规定的概率抽样方案时，才将区间用于总体推断。
5. 对 3.5 保存预热次数、全部逐次吞吐和机器环境；性能不足时先排除省电模式和后台高负载，再按同一预设方案重复测试并保留全部结果。
6. 归档代码版本标识、`algorithm_manifest.json`、测试脚本、JSON 报告和本说明文档。

交付包由以下命令生成，ZIP 内的 `PACKAGE_MANIFEST.json` 记录每个文件的大小和 SHA-256：


## 14. 扩展真实业务数据的建议

正式业务数据应与内置标注数据分开保存，并建立只读版本标识。3.2 建议覆盖平稳、阶跃、周期、噪声和异常尖峰时序；3.3 覆盖不同编码、缺失字段和超长记录；3.4 覆盖设备别名、时间漂移、重叠窗口和无匹配记录；3.6、3.9 应依据项目数据字典配置必填字段、值域、时效窗口和主数据集合。新增数据不得删除内置边界用例，且应在报告中记录数据摘要和指纹。
