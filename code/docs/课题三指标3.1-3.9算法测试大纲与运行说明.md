# 课题三指标 3.1-3.9 算法测试大纲与运行说明

## 1. 目的与验收原则

本文给出“面向离散制造垂域模型的自动化数据治理系统”指标 3.1-3.9 的算法文件、公开基准、通过判据、运行方法和证据边界。

验收分数只来自固定版本、可追溯的四个公开基准：MetroPT-3、UCR FordA、UCI SECOM 和 HoloClean Hospital。加载器会按照 `governance/benchmark_data/public/benchmark_manifest.json` 校验文件大小和 SHA-256。单元测试中的手写数据仅验证非法输入、边界条件和安全行为，不计入指标得分。

## 2. 数据与文献依据

| 基准 | 公开依据 | 固定测试内容 | 使用指标 |
|---|---|---|---|
| MetroPT-3 | UCI，DOI `10.24432/C5VW3R`，CC BY 4.0 | 官方完整 1,516,948 行、全部 15 个传感器通道和四个维护区间 | 3.1-3.9 |
| UCR FordA | UCR Time Series Classification Archive | 完整 TRAIN 与 TEST，共 4,921 条、每条 500 点 | 3.1、3.2、3.3、3.5、3.6、3.8、3.9 |
| UCI SECOM | UCI，DOI `10.24432/C54305`，CC BY 4.0 | 全部 1,567 条半导体制造记录、590 个传感器字段和原始缺失值 | 3.1、3.3、3.6、3.8、3.9 |
| HoloClean Hospital | PVLDB 2017 与官方仓库固定 commit | 全部 1,000 行脏数据和 19,000 个清洁真值单元格 | 3.1、3.3、3.6、3.8、3.9 |

选择依据、许可证、固定 commit 和源归档指纹见 `REFERENCES.md` 与公开数据清单。MetroPT-3 和 SECOM 是工业数据；FordA 是汽车发动机时序分类数据；Hospital 是公开关系数据质量基准。3.4 与 3.7 只使用带有官方维护区间关系表的 MetroPT-3，其他基准不构造替代关系表。

## 3. 环境与统一运行

- Python 3.11 或更高版本。
- 核心指标测试仅使用 Python 标准库。
- 所有命令从 `code` 目录执行。
- 性能测试应固定机器、电源策略和后台负载。

```bash
cd code
python3 --version
python3 tools/fetch_full_benchmarks.py
python3 run_indicator_tests.py all
```

单项运行：

```bash
python3 run_indicator_tests.py 3.1
# 将 3.1 替换为 3.2 至 3.9
```

指定证据目录：

```bash
python3 run_indicator_tests.py all --report-dir ./data/reports/acceptance
```

运行完整单元与并发回归：

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

退出码 `0` 表示所选单元测试与公开基准均通过。JSON 报告记录 Python、操作系统、处理器、Git commit、算法清单 SHA-256、源码组合哈希、公开数据来源和逐项结果。

## 4. 指标 3.1：序列、关系数据存储与压缩

**算法文件：** `governance/indicator_3_1.py`，原子写入和文件锁见 `governance/common.py`。

**真实输入：**

- MetroPT-3 全部 1,516,948 条、15 通道传感器记录。
- FordA 完整 TRAIN 与 TEST 的 4,921 条时序。
- SECOM 全部 1,567 条关系记录，每条包含 590 个传感器字段、标签和时间戳。
- HoloClean Hospital 全部 1,000 条关系记录。

**测试步骤：**

1. MetroPT-3 CSV 和 FordA TS 文件流式执行 Gzip 无损压缩与回读。
2. SECOM 与 Hospital 关系记录写入 SQLite，并生成数据库 Gzip 备份。
3. 核对各数据集的完整记录数、无损解压字节、关系查询结果和备份数据库完整性。

**通过判据：** `sequence_round_trip`、`relation_round_trip` 和 `relation_backup_round_trip` 全部为真。3.1 只要求具备存储、压缩和无损回读能力，压缩比作为证据披露。

## 5. 指标 3.2：工业时序数据压缩比达到 9:1

**算法文件：** `governance/indicator_3_2.py`。已有成果 REGER、BOS、TS_2DIFF+BOS 通过 `integrations/group_research/adapter.py` 提供独立编解码能力，不参与本项验收结果的计算。

**真实输入：** UCI MetroPT-3 官方完整归档的全部 1,516,948 行、15 个传感器通道，以及 UCR FordA 完整 TRAIN 与 TEST 的 4,921 条、2,460,500 个时序点。不跳行、不选择表现较好的子集。

**口径：**

- 原始传感器载荷按七个模拟量 Float64（每值 8 字节）和八个数字量 UInt8（每值 1 字节）计算；时间戳不计入传感器压缩口径。
- 模拟量使用固定误差界量化、时间方向差分和 zlib 熵编码；数字量使用无损二值编码和 zlib 熵编码。整份数据使用这一套确定性方法，不按测试结果切换算法。
- TP2、TP3、H1、DV_pressure、Reservoirs 的绝对误差界为 `0.001`，Oil_temperature 为 `0.0125`，Motor_current 为 `0.01`；八个数字量必须逐值无损。
- 数据按 65,536 行流式分块。每个块、每个通道均执行编码、解码和逐值核验，同时累计原始字节与实际压缩载荷字节。
- 报告保存总体压缩比、全部数据块压缩比、全部通道压缩比、每个模拟量最大绝对误差、数据总行数与总值数，不能只报告总体中的有利结果。
- FordA 对每条完整序列在两种既有误差有界编码中选择载荷较小者，逐条执行解码与误差核验，并披露最差序列、分位数和全部 4,921 条结果。

**通过判据：** MetroPT-3 的总体、最差数据块和最差通道压缩比均不低于 9.0；FordA 的总体和最差序列压缩比均不低于 9.0；所有有损通道满足声明误差界，所有无损通道逐值一致；记录数和通道数与官方清单一致。

**重要边界：** 该结论适用于上述明确的原始字节类型和误差界。压缩比不包含 CSV 文本格式、时间戳、容器索引或网络协议开销，不能外推为其他数据类型或其他误差容忍度下的结果。

## 6. 指标 3.3：序列、关系数据解析准确率不低于 95%

**算法文件：** `governance/indicator_3_3.py`。

**真实输入与真值：** MetroPT-3 全部 1,516,948 行、FordA 完整 TRAIN 与 TEST、SECOM 全部 1,567 行和 Hospital 全部 1,000 行。文件声明的完整记录数、列结构和标签范围作为解析真值。

**测试步骤：** 使用对应格式解析器遍历四个完整数据集，核对记录数、字段数、数值点数、标签和文件结束位置；非法 JSON、非法 UTF-8、标量 JSONL 和缺失字段等只作为健壮性回归，不计入正式准确率。

**通过判据：** 四个数据集各自的完整记录解析准确率均不低于 95%，报告保留各数据集分母、失败数和 Wilson 95% 描述性区间。

## 7. 指标 3.4：序列、关系数据对齐准确率不低于 90%

**算法文件：** `governance/indicator_3_4.py`。

**真实输入与真值：** MetroPT-3 全部 1,516,948 条传感器记录和四个官方维护区间。时间戳位于公开闭区间内时，真值为对应维护编号；窗口外为负例。

**测试步骤：** 设备实体规范化后，以零时间容差执行闭区间对齐；逐条比较预测故障编号和公开窗口真值。样本同时包含窗口内正例和窗口外负例。

**通过判据：** `alignment_accuracy_percent >= 90.0`。报告必须包含正例数、负例数、公开窗口数、时间容差和 Wilson 区间。

## 8. 指标 3.5：时序数据采集频率达到 1.1 kHz

**算法文件：** `governance/indicator_3_5.py`。

**真实输入：** MetroPT-3 全部 1,516,948 条记录和 FordA 完整 TRAIN 与 TEST 的 2,460,500 个时序点。

**测试步骤：**

1. 分别按固定批量完整回放两个时序基准到固定容量环形缓冲区。
2. 预热一次后重复七次。
3. 每次核对接收数量、首样本、末样本和丢失数。
4. 记录最低、中位、最高吞吐和变异系数。

**通过判据：** 两个数据集各自七次运行中的最低软件接收吞吐均不低于 1,100 条记录/秒，所有运行均无丢失且首末记录一致。

**重要边界：** 该结果验证真实高频文件在 Python 软件边界的接收和缓冲能力，不覆盖传感器、采集卡、驱动、时钟同步和网络链路。现场整机验收需要另接真实采集硬件。

## 9. 指标 3.6：四维质量指标不低于 95%

**算法文件：** `governance/indicator_3_6.py`。

**真实输入：** MetroPT-3、FordA、SECOM 和 Hospital 完整数据。公开数据中的自然缺失与错误原样保留，不人工注入异常。

**四个维度：**

- 完整性：必填字段/传感器单元格的非缺失比例。
- 一致性：时间顺序、字段结构和分类值的一致比例。
- 时效性：相对于各公开归档观察窗口结束时刻的有效比例。
- 有效性：有限数值、时间戳和标签值域的有效比例。

**通过判据：** 对每个可评价维度取四个数据集中的最低值，所有最低值均不低于 95%。不含时间戳的数据集将时效性标记为不可评价，不以满分代替。

**重要边界：** 归档数据不能按 2026 年当前时间评价业务新鲜度，否则所有历史公开数据都会失去可比性。报告中的时效性是“归档观察窗口内的事件时间有效性”，不能解释为当前生产数据时效。

## 10. 指标 3.7：序列、关系数据融合

**算法文件：** `governance/indicator_3_7.py`，复用 3.4 的对齐实现。

**真实输入：** MetroPT-3 全部 1,516,948 条传感器记录和四条官方维护区间关系记录。

**测试步骤：** 按设备和故障时间窗执行左融合；逐行核对故障编号真值，并检查 `source_row`、时间戳和值未改变。窗口外样本必须保留且不能附加关系字段。

**通过判据：** 融合输出行数等于输入序列行数，逐行真值准确率为 100%，原始行保持率为 100%，且同时存在命中和未命中样本。

## 11. 指标 3.8：工业异构数据规范化测试框架

**算法文件：** `governance/indicator_3_8.py`。

**公开测试范围：** MetroPT-3、FordA、SECOM 和 Hospital 四个完整公开基准分别规范化为统一的 `sequence_record`、`relation_record` 或 `cell_truth` 中间表示。

**通过判据：** 四个数据集的规范化记录数与完整源数据一致，必需字段保留率和规范化成功率均不低于 95%。

注册表还提供 TSV、分号、管道、JSONL、INI 和 XML 适配器；这些通用适配器保留为功能能力，但没有使用自建样例扩充正式基准分数。

## 12. 指标 3.9：工业数据质量综合测评

**算法文件：** `governance/indicator_3_9.py`，基础四维复用 3.6。

**真实输入与真值：** MetroPT-3、FordA、SECOM 完整数据，以及 HoloClean Hospital 的全部 19,000 个清洁真值单元格。

**八个维度：** 完整性、一致性、归档时效性、有效性、唯一性、参照完整性、清洁真值单元格准确率、可追溯性。

**通过判据：** 维度数不少于六，所有维度均不低于 95%。HoloClean 真值准确率按脏表单元格与清洁真值逐格比较。

**重要边界：** HoloClean 的真值维度描述输入关系数据本身有多少单元格正确，不是本系统自动修复的 precision、recall 或 F1。要验证自动修复能力，必须让修复模块输出候选修复，再与 509 个错误单元格真值独立比较。

## 13. 结果判读

1. 确认退出码为 `0`，并检查 JSON 中每项 `passed`。
2. 核对 `benchmark_provenance`、文件 SHA-256、源码组合哈希和环境信息。
3. 3.2 核对官方完整行数、全部 15 个通道、总体压缩比、最差数据块、最差通道、全部块结果和逐通道误差，不只看总体压缩比。
4. 3.3、3.4 保存样本量、正负例、准确率、失败列表和描述性 Wilson 区间。
5. 3.5 保存七次原始吞吐、最低值、变异系数和机器环境，不把软件结果写成硬件结果。
6. 3.6 的时效性注明归档观察窗口口径。
7. 3.8 分别核对四个完整基准的源记录数、规范化记录数和失败数。
8. 3.9 区分“输入数据真值准确率”和“自动修复算法效果”。
